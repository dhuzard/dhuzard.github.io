AI insights & literature grounding¶

The tool includes an optional AI layer that turns the analysis tables into plain-language prose, drafts a methods paragraph, triages data-quality issues, and can attach supporting literature. It is designed around one non-negotiable rule:

The AI never sees your raw data

Every AI feature operates on small, derived, aggregated summary tables — never the raw per-minute recordings. The model interprets numbers you already computed; it does not compute them. This is both a privacy stance (your recordings stay on your machine) and a hallucination defence (the model is handed the numbers and constrained to cite them, so it cannot invent a statistic).

All AI features are off by default, opt-in, and clearly disclose what leaves your machine before anything is sent.

Plain-language results narrative¶

What it does. Converts the analysis tables — which non-coders often can’t read — into a readable paragraph, for example:

“KO showed ~32% lower dark-phase locomotion than WT (rank-biserial 0.6, exploratory p = 0.03, n = 6/6); circadian amplitude was reduced and acrophase delayed ~1.5 h. Exploratory only.”

The narrative always carries the sample size next to each claim, injects the exploratory-statistics disclaimer, and is forbidden from upgrading “exploratory” to “significant” or “confirmatory”.

Methods-section drafter & QC triage¶

  • Methods drafter — from your run configuration and provenance manifest, drafts a reproducible methods paragraph (binning, alignment, baseline window, cosinor period, tests, FDR). Near-zero hallucination risk because it transcribes your configuration.

  • QC / confound triage — reads the quality report and exclusion log and turns them into plain-language actions (“cage M07 is 40% missing in its baseline window — consider excluding”).

Grounded Q&A (tool-calling)¶

Because the analysis functions are clean, table-in/table-out functions, they can be exposed to the model as callable tools. When you ask a question, the model calls the real analysis functions to get numbers rather than inventing them — the safest possible way to combine an LLM with quantitative results. A fully offline scripted provider keeps this testable with no network.

Choosing an engine¶

Provider

What leaves your machine

Offline (default)

Nothing. A deterministic templated narrative — no network, no keys. The feature works out of the box and is fully reproducible.

Local (Ollama)

Nothing leaves your machine — a local model generates the prose.

Cloud (bring-your-own-key)

Only the summary tables, sent to the provider you choose with your own API key. The egress is disclosed in the UI before you send.

Whichever engine you pick, the exact payload the model saw, the prompt, the model id and the token usage are written into the export bundle (insights/payload.json, insights/narrative.md) and hashed into manifest.yaml — so an AI narrative is as traceable and reproducible as every other output.

AI circadian scoring (Circadiem)¶

Separately, the optional Circadiem feature scores circadian plots using a vision model — it renders the actogram/profile to an image and returns a structured circadian-quality score. It can run against a local Circadiem service (nothing leaves your machine) or a hosted one.

Literature grounding¶

An optional, opt-in literature search (via Europe PMC) can attach relevant references to a finding using generic keyword queries. It is offline by default. Independently, the tool ships a curated, offline corpus of DVC studies (see Literature references) that ranks against your analysis with no network at all — so every analysis can point you to the paper that validates it.

Always read the primary source

The literature features surface candidate references to help you — they are not a substitute for reading and citing the primary article (by its DOI) before you rely on a finding.
