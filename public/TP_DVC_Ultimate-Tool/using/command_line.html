The command line¶

Everything the app does is also available from a terminal through the udwa command. This is useful for scripting, batch processing and automation. The CLI holds no logic of its own — it calls the same tested library — so anything you can do here is exactly what the app does.

Tip

udwa is installed with the package. If you used a virtual environment, call it as .\.venv\Scripts\udwa.exe (Windows) or ./.venv/bin/udwa (macOS/Linux), or equivalently python -m udwa.cli.

Commands at a glance¶

Command

Purpose

udwa tools

List the registered grounded analysis tools

udwa plan

Print the ordered specialist run plan for a goal

udwa ingest

Turn DVC data (CSV or live API) into a tidy long CSV

udwa analyze

Run one analysis tool on a long CSV

udwa report

Render selected analyses to a PDF

udwa sanity

Data-quality traffic-light check on metric CSVs

udwa monitor

Daily cage-batch sanity monitor with email alerts

udwa tools — discover analyses¶

udwa tools                        # list all tools
udwa tools --specialist NAME      # filter by specialist role

udwa plan — see the run plan¶

udwa plan "circadian rhythm + welfare"

Prints the deterministic, ordered set of specialist steps and the tools each one runs — a preview of how the platform would approach your goal.

udwa ingest — get data in¶

From CSV files (offline, no network needed):

udwa ingest --csv data/examples/Cohort7623_animal_loc__index_smoothed.csv -o long.csv

From the live DVC API (needs the ingest extra):

udwa ingest --api --cage-ids S44S-05900 S81Z-16921 --metric-ids 1 3 \
            --start 2024-01-01 --stop 2024-01-07 -o long.csv

Useful flags: --aggr-type {HOUR,MINUTE} (default HOUR), --api-key, --base-url.

Managing your API key (no output file needed):

udwa ingest --test-key                 # check the stored/available key
udwa ingest --save-key YOUR_KEY        # save it to the encrypted local store
udwa ingest --list-metrics             # list metric IDs
udwa ingest --search-cages S81Z-       # find cage IDs by pattern

udwa analyze — run one analysis¶

udwa analyze -i long.csv --tool summarize_circadian_cosinor
udwa analyze -i long.csv --tool summarize_activity_bouts -p threshold=auto -o bouts.csv

  • -i/--input — the long CSV (required)

  • --tool — the analysis to run (see udwa tools)

  • -p/--param key=value — pass tool parameters (repeatable)

  • -o/--out — write a CSV; omit to print JSON to the screen

udwa report — make a PDF¶

Render one or more analysis tables into a PDF (needs the report extra):

udwa report -i long.csv \
            --tool summarize_activity \
            --tool summarize_circadian_cosinor \
            -o report.pdf --title "My study"

udwa sanity — quality check¶

Run the data-sanity traffic-light check on one or more metric CSVs:

udwa sanity data/examples/Cohort7623_animal_loc__index_smoothed.csv --md sanity.md

Useful flags: --csv-out OUT.csv, --warn-missing 5.0, --fail-missing 15.0, --light-on 07:00, --light-off 19:00, --timezone Europe/Paris.

Exit codes: 0 = PASS or WARN (data is usable), 2 = FAIL (quality issues severe enough to block analysis). Handy in scripts.

udwa monitor — daily monitoring¶

Run the sanity check on a saved cage watchlist, on demand or on a schedule:

udwa monitor --profile cohort-A                    # one-shot run now
udwa monitor --serve --profile cohort-A --at 07:00 # run forever, fire daily
udwa monitor --list                                # list saved profiles
udwa monitor --show cohort-A                        # show a profile

One-shot exit codes: 0 = PASS/WARN, 1 = hard error (no profile, unresolved key, API failure), 2 = FAIL (including “no data”). See Daily monitoring & email alerts for the full guide.
