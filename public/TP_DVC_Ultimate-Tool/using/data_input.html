Data input¶

This page explains what data the tool accepts and how it flows through the pipeline. You do not need to prepare anything special — a standard DVC export works directly.

The bundled example¶

Every install ships with a real DVC cohort recording so you can try the tool with no data of your own:

File (data/examples/)

Contents

Cohort7623_animal_loc__index_smoothed.csv

Full activity-index recording

Cohort7623_animal_loc__index_smoothed_5days.csv

A 5-day subset

Cohort7623_animal_loc__index_smoothed_4days-6mice.csv

A 4-day, 6-mouse subset

Cohort7623_events.csv

Matching cage/facility events

Load them from Import → “Load bundled example”.

Accepted formats¶

Format

Notes

DVC Metric CSV (wide)

The primary format, exported from the DVC Analytics platform. Columns start with day, hour, minute, relativeTime followed by per-subject value columns grouped under a *_TIMESTAMP prefix. The tool auto-detects this layout.

DVC Event CSV (optional)

A companion file of cage/facility events (INSERTED, REMOVED, CAGE_CHANGE, CAGE_OFFLINE/ONLINE, FACILITY_EVENT). Used for alignment and exclusion windows.

EMF electrode CSV

Per-electrode data (v_1…v_12, canonicalised to e01…e12) for spatial occupancy, entropy and RDI analyses. The 12 electrodes form a 4×3 grid.

Parquet / HDF5

Supported for very large exports via the optional formats extra (pip install -e ".[formats]").

What “long format” means¶

Whatever you feed in, the tool converts it to one tidy table — the long format — where every row is a single (subject × metric × timestamp) observation. Every analysis reads from this one table, so results are identical no matter where the data came from.

The four essential columns are:

Column

Meaning

timestamp_utc

The observation time (timezone-aware, UTC)

value

The measured value (e.g. activity index)

metric_name

Which metric this is

subject_id

Which animal / cage

The full long table also carries group_id, local time, ZT/light-dark phase, day/hour/minute, native bin size, and per-group summary columns. If you already have a warehouse export with the four essential columns, the tool accepts it as a long table directly.

Live DVC Analytics API¶

Instead of files, you can pull recordings straight from the DVC platform (needs the ingest extra). The tool uses an asynchronous submit → poll → download task flow and resolves your credentials in this order:

  1. a value you pass explicitly (in the app, or --api-key / --base-url on the CLI),

  2. the environment variables DVC_API_KEY / DVC_BASE_URL,

  3. an encrypted local key store.

The encrypted key store¶

Your API key can be saved locally, encrypted at rest with a per-user key (Fernet). The encryption key lives at ~/.udwa/.encryption_key (readable only by you) and the encrypted settings at ~/.udwa/api_settings.json. The default API endpoint is https://analytics.dvc.tecniplast.it.

Save and verify a key from the command line:

udwa ingest --save-key YOUR_API_KEY     # store it, encrypted
udwa ingest --test-key                  # confirm it works
udwa ingest --list-metrics              # see available metrics
udwa ingest --search-cages S81Z-        # find cage IDs by pattern

Key status is always explicit

The tool reports a structured key status — OK, ABSENT, DECRYPT_FAILED, or UNAVAILABLE (the optional encryption library isn’t installed) — each with an actionable message, so you’re never left guessing why a fetch failed.

Configuration you can set¶

Sensible defaults are built in, and every one is adjustable in the app (or via the CLI / config):

Setting

Default

Lights on / off

07:00 / 19:00

Timezone

Europe/Paris (IANA name)

Aggregation bin

Native, 1 min, 5 min, 1 h, 12 h or 24 h

Baseline window

−72 h to −24 h before the alignment event, mean method

Alignment

Label J0; per-group / per-subject overrides allowed

Exclusion rules

Per event type (e.g. cage change: 6 h before / 48 h after) — flag only by default; you opt into removal

Local time is derived from the recording, not assumed

DVC exports carry the recording site’s UTC offset on every timestamp. The tool uses that embedded, DST-correct offset to place each observation in the animal’s own local time — so a default Europe/Paris setting will never mis-phase data that was actually recorded elsewhere.
